# Заявки и подбор штор

## Текущий статус

Подбор штор проходит четыре шага: комната, материалы, необязательные размеры, контакты. Возврат сохраняет ответы и контактные поля. Источник из `?source=…` или `?context=…` попадает в резюме заявки. Иллюстрации маркированы как концепции и не являются результатом подбора.

`InquiryForm` используется для обсуждения проекта и последнего шага подбора. Есть постоянные подписи, встроенные сообщения об ошибках, проверка телефона и согласия, сохранение ввода при ошибке сети, защита от повторных нажатий. Успех показывается только после подтверждения API.

**Доставка в студию не подключена.** Локальный сервер сохраняет данные в `data/runtime/inquiries.jsonl` и отвечает:

```json
{"id":"…","status":"saved_locally","message":"Заявка сохранена в локальной версии. Доставка в студию ещё не подключена."}
```

В интерфейсе это ограничение сообщается до отправки и после успешного сохранения. Письма, сообщения и реальные заказы не создаются. Для прямой связи остаётся опубликованный телефон студии.

## Запуск и проверки

Сервер: `node server/index.mjs`. По умолчанию слушает `127.0.0.1:3001`; Vite проксирует `/api` на него. Общий сценарий запуска описан в корневом README.

Проверки API: `node --test server/inquiries.test.mjs`. Они используют временную папку и вымышленные контакты. Проверяются конкурентные повторы, валидация, обязательное согласие, положительные/необязательные размеры, ограничения размера, JSON и запреты чужого Origin.

При реализации компонент подбора дополнительно проверен в Chrome через отдельную Vite-страницу: отсутствие горизонтального переполнения на 320, 390, 768, 1024, 1440 и 1920 px; прохождение четырёх шагов; ошибки материала, размеров и согласия; сохранение размеров и контактов при возврате; сохранение ввода после ошибки API и повторная отправка; передача источника и ответов в запрос. Ответы API в этой браузерной проверке подменялись тестовыми; это проверка UI, а не доставки в студию.

Переменные сервера:

- `INQUIRY_PORT`, `INQUIRY_HOST` — порт и адрес прослушивания.
- `INQUIRY_DATA_DIR` — папка локального хранения, по умолчанию `data/runtime`.
- `APP_ORIGIN` — допустимые адреса фронтенда через запятую. По умолчанию `http://localhost:5180,http://127.0.0.1:5180`. Для другого origin задайте его явно.

`POST /api/inquiries` принимает JSON до 16 КБ. Обязательные поля: `name`, `phone`, `consent: true`, `requestId` (16–80 символов: буквы, цифры, `_`, `-`). Необязательные: `comment`, `context`, `email`, `selection`. Контакты валидируются на сервере. Неизвестные поля не сохраняются. `requestId` обеспечивает идемпотентность повторов и сохраняется вместе с записью; изменение содержимого под прежним идентификатором возвращает 409. Запись сериализована в рамках одного процесса. IP и User-Agent не записываются.

## Подключение рабочей доставки

Frontend может использовать `VITE_INQUIRY_ENDPOINT` вместо `/api/inquiries`. Рабочий сервис должен реализовать те же проверки и подтверждать результат только после фактического принятия заявки системой студии. Ответ `status: "sent"` разрешён только при реальном подтверждении доставки; иначе используйте ошибку или `saved_locally`. Клиент не имитирует доставку по одному успешному HTTP-коду.

До публикации необходимо подключить реальный сервис заявок, определить сроки хранения и удаления персональных данных, согласовать политику с владельцем и проверить доставку на согласованном тестовом обращении. Этот файловый backend предназначен для локальной проверки: он не заменяет промышленное хранилище, антиспам, эксплуатационные процедуры и интеграции исходного сайта. Файл с заявками нельзя публиковать или коммитить.
