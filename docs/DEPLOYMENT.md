## Почта

Адрес отправителя и получателя уведомлений: `vipdecordesign@yandex.ru`, согласован владельцем. Обычный пароль аккаунта не используется сервером. Яндекс SMTP SSL: `smtp.yandex.ru:465`, пароль приложения «VIP Decor сайт»; IMAP и пароли приложений разрешены с согласия владельца.

API сначала надёжно сохраняет заявку в `inquiries.jsonl`. Ответ `saved_locally` и health `delivery: local_only` относятся к этапу сохранения, а не к результату SMTP. Раз в минуту `vip-decor-mail.timer` запускает `scripts/inquiry-mailer.py`. Подтверждённые SMTP-отправки повторно не отправляются; состояние хранится в `mail-delivery.sqlite`. При определённом отказе — до 5 попыток. При разрыве во время передачи — `hold`, без автоматического повтора во избежание дубля; сначала нужно сверить Message-ID с почтовым ящиком. Статус `accepted` означает принятие Яндекс SMTP, не автоматически подтверждение папки «Входящие».

Проверка 9 октября: тестовая заявка `10596e1a-c47f-4d58-8d86-3998dc9d6fcd` создана через API, видна в авторизованной CMS, принята SMTP и найдена по точному Message-ID во «Входящих» через IMAP read-only. Тестовые контакты вымышлены; звонить не нужно.

```sh
systemctl status vip-decor vip-decor-mail.timer
journalctl -u vip-decor-mail.service --since today
sqlite3 /var/lib/vipdecor/runtime/mail-delivery.sqlite 'SELECT id,state,attempts,error FROM delivery;'
```

## Копии и обслуживание

`vip-decor-backup.timer`: ежедневно в 02:00 UTC / 05:00 МСК. С 10 октября скрипт использует online backup SQLite без остановки сайта и CMS. На время копирования приостанавливается только таймер почтовой отправки; уже работающий отправитель завершается сам, после чего таймер восстанавливается. Все базы копируются через SQLite backup API, а не копированием живых WAL-файлов. Хранение на VPS — 7 суток. Первая копия создана и скачана в папку «VIP Decor — резервная копия 2026-10-09» на рабочем столе; копии на самом VPS не защищают от потери VPS. Для постоянного внешнего резервирования потребуется отдельное хранилище.

```sh
systemctl start vip-decor-backup.service
systemctl list-timers vip-decor-backup.timer
# Перед восстановлением остановить сайт и почтовый сервис.
# Распаковать нужный runtime.tar.gz в /var/lib/vipdecor,
# восстановить владельца vipdecor и права, затем запустить службы.
```

Нельзя заменять runtime файлами из Git или сборки. Обновление кода не должно перезаписывать редакторские данные. Перед новым релизом сохранить резервную копию, загрузить новую отдельную папку releases, проверить её, затем переключить current и перезапустить сервис.

## DNS и HTTPS

Уточнение 9 октября, 22:49 МСК: WHOIS самого реестра TCI уже содержит `ns5.hosting.reg.ru` / `ns6.hosting.reg.ru` (обновление базы 19:48:01 UTC). Однако все пять авторитетных серверов зоны `.ru` — a/b/d/e/f.dns.ripn.net — ещё публикуют делегацию на Tilda. Таким образом, смена зарегистрирована, но публикация DNS-делегации ещё не завершена. Это не только кеш браузера. Подробные результаты и оставшиеся условия: [deployment-20261009/dns-transition.md](deployment-20261009/dns-transition.md).

REG.RU принял смену NS на `ns5.hosting.reg.ru` / `ns6.hosting.reg.ru`. Новая зона: A @ и www → 151.248.116.210, MX 10 mx.yandex.net., SPF `v=spf1 redirect=_spf.yandex.net`, существующий DKIM `mail._domainkey` перенесён без изменения. Записи проверены на обоих новых авторитетных DNS. Входящая почта домена остаётся в Яндексе.

Сертификат Let's Encrypt для `vip2d.ru` установлен и действителен до 7 января 2027. HTTPS проверен на VPS с правильным именем домена и проверкой сертификата: `/api/health` — 200. HTTP перенаправляется на HTTPS.

На момент проверки реестр `.ru` ещё указывал старые NS Tilda. Поэтому публичный домен пока может открывать старый сайт. Для `www` сертификат ещё не получен: старый DNS-интерфейс Tilda не принимает многоуровневое имя TXT для проверки. `vip-decor-tls.timer` каждые 5 минут проверяет разрешение обоих имён на новый IPv4. После распространения DNS он выпускает сертификат на оба имени через webroot, включает HTTPS-перенаправление www → vip2d.ru и отключает себя. Попытки выпуска при ошибке ограничены одной в час. Скрипт: `deploy/finish-tls.py`. До завершения этой операции HTTPS для www не обслуживается.

Для основного сертификата настроено webroot-продление и `certbot.timer`, после продления nginx перезагружается. Полный цикл автоматического продления через публичный DNS пока не проверен; это зависит от распространения нового адреса.

```sh
journalctl -u vip-decor-tls.service --no-pager
systemctl status vip-decor-tls.timer
certbot certificates
# После завершения DNS и выдачи обоих имён:
certbot renew --dry-run --cert-name vip2d.ru
```

Для отката делегирования прежние NS: `ns1.tildadns.com`, `ns2.tildadns.com`; прежний A: 176.57.65.40. Старый сайт и его почтовые записи сохранены. В старой зоне остался безвредный TXT `_acme-challenge` от первичного выпуска сертификата.

Дополнительные проверки: 51 страница открыта в Chrome; 1 151 файл медиа каталога и 79 фотографий отзывов ответили 200. Тестовая заявка переведена в «Завершена» через защищённый API CMS, изменения сохранены. В журнале отправок одна доставка с одной попыткой; повторные запуски сервиса не породили дублей.
