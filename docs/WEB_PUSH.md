# Web Push в CMS VIP Decor

## Включение

Откройте https://vip2d.ru/admin, войдите и нажмите «Уведомления» → «Включить на этом устройстве». Разрешение запрашивается только после нажатия. Затем нажмите «Проверить уведомление»: этот запрос не создаёт заявку и не отправляет email. Надпись об очереди не подтверждает получение: должно появиться системное уведомление. Подписка действует отдельно в каждом браузере/профиле/устройстве; выключение в этом же окне удаляет серверную подписку. Выход из CMS не отключает push. Уведомления не содержат имён, телефонов, email и комментариев.

На iPhone/iPad нужен iOS/iPadOS 16.4+ и установленное приложение: Safari → «Поделиться» → «На экран Домой», запуск с иконки, вход в CMS и включение уведомлений. На Mac Safari нужен macOS Ventura или новее. Chrome/Edge/Firefox используют стандартный Push API; доступность определяется по функциям браузера. Доставка зависит от ОС, разрешений, фоновой работы браузера, сети и доступности push-службы. Поддержка по документации не является проверкой конкретного устройства.

Если ранее нажали «Запретить», сначала разрешите уведомления для сайта в настройках браузера. При потере/изменении подписки панель предложит включить её заново. При истечении сессии сначала войдите снова. После смены VAPID-ключей все устройства потребуется переподписать, поэтому ключи нельзя регулярно пересоздавать.

## Устройство сервиса

- `public/admin-sw.js`: стандартный service worker со scope `/admin`, без кеширования страниц и данных CMS. Каждое push показывает уведомление. Нажатие открывает `/admin?inquiry=<id>`; авторизация обязательна. Другая редактируемая вкладка не перезагружается, чтобы не потерять правки.
- `public/admin/manifest.webmanifest`: установка отдельной CMS на домашний экран. Манифест подключён только на административных страницах.
- `server/push.mjs`: зашифрованная доставка Web Push через VAPID. SQLite `push.sqlite` в постоянном runtime хранит подписки, обработанные ID и очередь. Она входит в резервную копию runtime.
- Новая запись сначала сохраняется в `inquiries.jsonl`. Сразу запускается scan очереди; каждые 15 секунд сервер подбирает пропущенные записи после сбоя. Открытая вкладка не нужна. Почтовый sidecar работает независимо.
- При первом включении сервиса прежний журнал помечается обработанным, без рассылки старых заявок. Подписчик получает только обращения, созданные после подключения его устройства.
- Уникальная пара заявка/подписка защищает от повторов API и повторных scan. 404/410 удаляют недействительную подписку. Сетевые ошибки, 429 и 5xx допускают до 5 попыток с экспоненциальной задержкой, TTL — 24 часа. Неустранимые ошибки прекращают повторы. Статус `accepted` означает принятие push-службой, а не подтверждение показа на устройстве.
- После неопределённого сетевого результата или перезапуска возможна повторная доставка; постоянные Topic и tag сворачивают повторные уведомления. Web Push не гарантирует строго однократный показ.
- Конечные состояния очереди хранятся 7 дней; журнал обработанных ID сохраняется для идемпотентности. Не выводите тела подписок и ключи в логи.

## Настройки и защита

Сервер читает JSON `{publicKey, privateKey, subject}` по `PUSH_VAPID_FILE`. Production: `/etc/vip-decor/push-vapid.json`, root:root 0600, передача сервису через systemd `LoadCredential`. Ключ создаётся на VPS библиотекой `web-push` единожды, не попадает в Git, HTML или API. API отдаёт только publicKey. Отсутствие настройки отключает push, сохраняя работу сайта. Повреждённый ключ останавливает запуск, чтобы не показывать ложную готовность.

Управление подпиской, проверка и тест находятся в `/api/cms/push/`, используют существующие cookie, Origin и CSRF. Подписка привязана к пользователю; доступ к чужой подписке запрещён. До 20 устройств на пользователя; тест — не чаще раза в минуту. HTTPS endpoints ограничены службами Google FCM, Mozilla Push и Apple Push, ключи проверяются до сохранения.

Нужен исходящий HTTPS к `fcm.googleapis.com`, `*.push.services.mozilla.com`, `*.web.push.apple.com`. Не отключайте проверку TLS. Backend сохраняет только код ошибки провайдера, без его ответа с адресом подписки.

## Обслуживание

```sh
systemctl status vip-decor vip-decor-mail.timer
journalctl -u vip-decor --since today
# Не выводит ключи/подписки/контакты:
sqlite3 /var/lib/vipdecor/runtime/push.sqlite 'SELECT state,count(*) FROM jobs GROUP BY state; SELECT count(*) FROM subscriptions;'
```

`deploy/backup.sh` сохраняет runtime, site.env и, если есть, VAPID JSON в root-only каталоге резервной копии. При восстановлении верните прежний VAPID-файл и runtime вместе. Пароль SMTP сохраняется отдельно по существующей процедуре. Никогда не заменяйте runtime содержимым сборки.
