# CMS — VIP DECOR DESIGN

Панель управления: `/admin`. Блог, товары и заявки хранятся на сервере; браузер не является хранилищем CMS. Почта не подключена.

## Первый запуск

Нужен Node.js **24.15 или новее**.

```sh
npm install
npm run dev
```

Сайт и CMS: `http://127.0.0.1:5180`; API: `127.0.0.1:3001`.

В другом терминале из папки проекта:

```sh
npm run cms:open
```

Команда открывает первый вход с одноразовым ключом, не печатая его в терминал. Вы задаёте собственные имя администратора и пароль. После создания администратора ключ больше не действует; далее входите через `/admin`. Если браузер не открылся, локальный ключ находится в `data/runtime/cms-setup-token`: его можно вставить в форму первого запуска. Не публикуйте этот файл.

## Работа в панели

- **Обзор:** количество товаров, статей и заявок; быстрые переходы к разделам.
- **Статьи:** создание, редактирование, черновик/публикация, обложка, рубрика, SEO, вступление, разделы, источники и связанные статьи. Текст разделов выводится с экранированием; HTML не нужен. Существующие таблицы и ссылки сохраняются. Адрес опубликованной статьи сохраняйте постоянным.
- **Товары:** название, описание, категории, артикул, цена, изображения, свойства и варианты. Варианты имеют собственные цены: при изменении стоимости проверьте их отдельно. Черновики скрыты с публичного сайта. Исходные идентификаторы и товарные адреса сохраняются.
- **Заявки:** контакты, комментарий, источник, параметры подбора и содержимое заказа; статусы «Новая», «В работе», «Завершена», «Спам» и заметка менеджера. Существующий журнал заявок также доступен в панели. Письма и сообщения автоматически не отправляются.

Публичные данные читаются из CMS. Публикация и снятие с публикации отражаются при следующем открытии/обновлении страницы без сборки. Блог отдаёт актуальный HTML, метаданные и JSON-LD с сервера, включая новые адреса. Скрытые статьи возвращают 404. При сохранении из двух вкладок устаревшая версия получает конфликт, чтобы не затереть чужое изменение.

## Где лежат данные

Каталог и блог импортируются **один раз** из `src/data/site-content.json` и `content/blog/*.json`. Исходные файлы остаются архивным снимком; повторный `npm run build` не отменяет правки в CMS. После первого импорта редактируйте сайт через `/admin`, а не через архивные JSON.

Рабочее хранилище — `data/runtime/` (или `INQUIRY_DATA_DIR`): SQLite, изображения CMS и журнал `inquiries.jsonl`. Вся папка исключена из Git. Хранить её нужно на постоянном диске. Временная файловая система/serverless без постоянного тома для этого варианта не подходит.

Для согласованной резервной копии остановите процесс API, скопируйте **всю** папку рабочего хранилища в защищённое место и запустите API снова. Восстанавливайте её также при остановленном процессе. Не храните копии внутри `public` или `dist`. Исходные JSON не являются резервной копией редакторских изменений и заявок.

## Запуск собранного сайта

```sh
npm run build
APP_ORIGIN=https://your-domain.example NODE_ENV=production npm start
```

`npm start` обслуживает сайт, CMS, API, актуальный блог и sitemap одним Node-процессом. По умолчанию он слушает `127.0.0.1:3001`; перед ним нужен HTTPS reverse proxy. Передайте собственный домен в `APP_ORIGIN`, сохраните заголовок Host и проксируйте весь сайт на этот процесс. При первом развёртывании также нужны `server/`, зависимости, `src/data/site-content.json`, `src/data/blog.json`, `src/data/yandex-reviews.json` и `content/blog/` для импорта. Проще разворачивать весь проект, исключая рабочие секреты и чужие runtime-данные. Простая загрузка `dist` на статический хостинг не запускает CMS. Не раздавайте `dist/server` как статические файлы.

Переменные:

| Переменная | Назначение |
| --- | --- |
| `APP_ORIGIN` | Точные допустимые адреса сайта через запятую |
| `INQUIRY_DATA_DIR` | Постоянная папка данных |
| `PORT` / `INQUIRY_PORT` | Порт собранного сервера; для dev — `INQUIRY_PORT` |
| `INQUIRY_HOST` | Адрес прослушивания, по умолчанию loopback |
| `CMS_API_TARGET` | Необязательный адрес API для Vite dev/preview |
| `CMS_ADMIN_URL` | Адрес сайта для `npm run cms:open` |
| `NODE_ENV=production` | Production-режим, защищённая cookie через HTTPS |

Для локального просмотра production-сборки: `npm start`, затем `http://127.0.0.1:3001/admin`. Можно также использовать `npm run preview` при работающем API; сборка SSR обязательна.

Аутентификация: пароль хранится как scrypt-хеш, сессия — в HttpOnly cookie, изменения защищены проверкой Origin и CSRF. У административных страниц установлен noindex; личные данные заявок доступны только после входа. Внешняя доставка, платежи и проверка реальных остатков остаются отдельными интеграциями.

## Проверки

```sh
npm test
npm run build
npm run qa:cms
```

`qa:cms` запускает собранный сервер на свободном порту с отдельной временной папкой. Создаёт вымышленного администратора и тестовые данные, проверяет публикацию, скрытие, работу форм и сохранение после перезапуска. Рабочую базу эти проверки не изменяют.

Эта реализация не публикует сайт на vip2d.ru. Подключение домена, HTTPS, постоянного хранилища и проверка на хостинге выполняются при развёртывании.
