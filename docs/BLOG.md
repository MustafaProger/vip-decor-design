# Блог об интерьере и доме

## Где смотреть

- `/blog` — все статьи; ссылка в шапке, футере и блоке на главной.
- `/blog/category/interior` — интерьер, цвет, материалы, стили, освещение и обновление дома.
- `/blog/category/art-and-decor` — картины, декор и интерьерные акценты.
- `/blog/category/textiles` — шторы, тюль, жалюзи, карнизы, покрывала и подушки.
- Постоянный адрес статьи: `/blog/<slug>`. Не меняйте `slug` после публикации без постоянного перенаправления со старого адреса.

Рубрики появляются только при наличии опубликованных статей. Отдельные пустые страницы под каждую комнату, стиль или близкий запрос не создаются. По мере появления самостоятельных материалов редактор может добавить рубрику в `content/blog/categories.json`.

## Как редактировать

Все исходники статей находятся в `content/blog/`. Одна статья — один JSON-файл с обычными русскими текстами. Компоненты React менять не нужно. Откройте нужный файл и меняйте только значения полей, сохраняя кавычки и запятые. Не редактируйте `src/data/blog.json`: это автоматически собранная копия.

| Поле | Назначение |
| --- | --- |
| `status` | `draft` — черновик, отсутствует в публичных данных, HTML и sitemap; `published` — включить в следующую сборку |
| `slug` | Постоянная латинская часть адреса с дефисами |
| `category` | Код существующей рубрики |
| `title` | Единственный H1 статьи и название карточки |
| `seoTitle` | Уникальный title для поиска; название компании добавляется автоматически |
| `description` | Уникальное краткое описание для поиска |
| `excerpt` | Короткое описание в карточке |
| `intro` | Самостоятельный ответ на главный вопрос статьи |
| `image` | Локальный путь, описание изображения, подпись и размеры |
| `sections` | Разделы статьи: `id`, `title`, абзацы `paragraphs`, необязательные `list`, `table`, `callout`, `links`, `citations` |
| `sources` | Проверенные источники: `id`, `title`, полный HTTPS `url`, пояснение `note` |
| `related` | Коды `slug` подходящих опубликованных материалов |

Оглавление строится из названий разделов; `id` раздела — стабильный якорь. `links` содержит пары `href`/`label` для внутренних ссылок на материалы, товары и услуги. `citations` — список `id` использованных источников, которые выводятся рядом с соответствующим разделом. Таблица задаётся `headers` (названия столбцов) и `rows` (массив строк).

Текст выводится средствами React с экранированием: HTML и JavaScript в поля не вставляют. Для ссылки используйте `links` или `sources`. Перенос внутри JSON-строки записывается как `\n`, новый абзац удобнее добавить отдельным элементом массива `paragraphs`.

После изменения:

```sh
npm run blog:prepare
npm run build
npm run preview
```

Откройте http://127.0.0.1:4173/blog. Если сервер preview уже запущен, достаточно обновить страницу; при изменении набора адресов перезапустите preview. При разработке после изменения текстов также выполняйте `npm run blog:prepare`, затем обновляйте страницу на 5180. При изменении рубрик или набора публикаций перезапустите сервер разработки.

## Как добавить статью

```sh
npm run blog:new -- kak-obnovit-gostinuyu "Как обновить гостиную без ремонта"
```

Создаст новый файл со статусом `draft`. Существующий файл команда не перезапишет. Заполните вступление, разделы, описания и проверенные источники, выберите рубрику и изображение. Поставьте `published`, когда материал готов к включению в сборку. Выполните команды выше и проверьте результат локально. Размещение файлов на публичном хостинге — отдельный шаг.

Не добавляйте вымышленных авторов, экспертных проверок и дат. В стартовых статьях нет даты публикации/обновления: локальная подготовка не выдаётся за состоявшуюся публикацию. При реальной публикации можно добавить подтверждённое `datePublished` в формате `YYYY-MM-DD`, при существенном редактировании — настоящее `dateModified`; они отобразятся в статье и JSON-LD. Дата автоматически из времени сборки не берётся. `lastmod` в sitemap сейчас намеренно не выставляется.

## Источники и изображения

Использованы существующие материалы компании: `data/source/pages/kakpodobrat.txt`, категории картин, тканей, покрывал и подушек. Исходный гид сохранён по `/kakpodobrat`. Готовых трёх запрошенных статей в исходной выгрузке нет; стартовые тексты подготовлены отдельно.

Фактическая основа:

- [Benjamin Moore](https://www.benjaminmoore.com/en-us/project-ideas-inspiration/interiors/bathroom-ideas-inspiration) — влияние освещения и проверка выкрасов при дневном и искусственном свете.
- [Canadian Conservation Institute](https://www.canada.ca/en/conservation-institute/services/care-objects/fine-art/basic-care-paintings.html) — сохранность живописи, свет, условия и крепление по весу.
- [GINETEX](https://www.ginetex.net/userfiles/files/Table_of_textile_care_symbols_en.pdf) — группы обозначений ухода за текстилем.
- [Материал компании](https://vip2d.ru/kakpodobrat) — подбор ткани-компаньона для покрывала и подушек; проверен по сохранённому исходнику сайта.

Палитры и пропорции — пояснённые варианты для примерки; расчёты показывают арифметику, не строительные нормативы. Нет обещаний наличия, новых цен, скидок и сроков. Разделы покрывал и подушек существуют, но в текущем снимке отдельных товарных карточек нет: ссылки ведут в информационные разделы, без утверждений о наличии.

Изображения взяты из проекта: `concept-living.webp`, `concept-bedroom.webp` (подписанные визуализации) и исходная фотография картины «Пионы» `/source-media/03589668073ff63d99.webp`. Скрипт подготавливает WebP в размерах 480, 800 и до 1200 px; оригиналы сохраняет. Есть `srcset`, `sizes`, размеры, alt, приоритет обложки и отложенная загрузка нижних карточек. Не добавлены вымышленные сведения об авторстве фотографий или лицензиях.

## SEO и HTML

При сборке React формирует семь полноценных HTML-страниц в `dist/blog/`: список, три рубрики, три статьи. Текст доступен без JavaScript, а после загрузки приложения используется тот же компонент. Заголовки, description, canonical и robots согласованы между HTML и клиентским переходом. Open Graph, `BlogPosting`/`CollectionPage` и `BreadcrumbList` выводятся в исходном HTML. При переходе из блога старые метаданные блога удаляются.

В `public/sitemap.xml` включаются только опубликованные статьи и непустые рубрики; `robots.txt` указывает sitemap. Проверяются уникальность основных метаданных, корректность адресов, изображений, ссылок на источники и связанные статьи. Ошибка в данных останавливает сборку. Черновики не попадают в генерируемый публичный набор.

Техническая основа: [рекомендации Google по JavaScript SEO](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics), [разметка Article](https://developers.google.com/search/docs/appearance/structured-data/article). Нет заявлений о гарантированных позициях, индексации или расширенном сниппете.

### Обязательная настройка хостинга

Выкладывать нужно весь `dist`, включая вложенные `blog/.../index.html`, изображения, robots и sitemap. Для `/blog` хостинг должен отдавать соответствующий HTML, а не общий SPA-файл главной. Неизвестный путь блога должен возвращать HTTP 404 с `dist/blog/404.html`. Конечные адреса в canonical не содержат завершающий `/`; `/blog/` и адреса статей с `/` перенаправляются на вариант без него. Эти ответы реализованы для Vite dev и preview.

Пример блока для Nginx в существующем `server` с `root`, указывающим на `dist`:

```nginx
location = /blog {
    try_files /blog/index.html =404;
}
location /blog/ {
    rewrite ^(/blog(?:/.*)?)/$ $1 permanent;
    try_files $uri/index.html =404;
    error_page 404 /blog/404.html;
}
location = /blog/404.html {
    internal;
}
```

Конфигурацию конкретного публичного хостинга нужно применить при выпуске. Публичный сайт в рамках этой задачи не изменён. Существующий Node API обслуживает заявки/отзывы и не заменяет статический хостинг. Общий SPA-рендеринг других страниц сайта в этой задаче не переведён на серверный.

## Проверка

```sh
npm test
npm run build
npm run preview
npm run qa:blog
```

`qa:blog` проверяет production preview: HTML с выключенным JavaScript, метаданные/разметку/sitemap, HTTP 404 и 301, страницы на пяти ширинах, изображения, Axe WCAG A/AA, рубрики, оглавление, переходы в каталог и блок главной. Результаты и снимки — `docs/qa-blog/`. Полевые Core Web Vitals и индексацию можно измерить после публикации; локальный проход не подтверждает их.
