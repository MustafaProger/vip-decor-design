# Ежедневное обновление отзывов

Реализовано и проверено локально 15 сентября 2026 года. Первый успешный серверный импорт: **18:28 МСК**, все **71 отзыв**, **79 фотографий**, **44 отзыва с фотографиями**. [Подтверждение API и состояния](qa-reviews-daily/sync.json).

## Поведение сайта

- Сначала отзывы с фотографиями работ, затем без фотографий. Внутри каждой группы сохраняется порядок источника.
- На главной — три отзыва и кнопка «Все отзывы» на `/projects`.
- На `/projects` — один заголовок и короткая вводная строка, первая порция из девяти отзывов. При достижении конца добавляются следующие девять; доступна и кнопка «Показать ещё».
- Клиент получает данные через `GET /api/reviews`. Открытие страниц не обращается к Яндексу и не запускает импорт. При недоступности API используется последний ответ текущей сессии или проверенный снимок из сборки.

## Как работает обновление

`server/index.mjs` при старте проверяет срок последней попытки и ставит следующий таймер через 24 часа от неё. Если срок уже прошёл, обновление выполняется сразу. Для всех посетителей используется один серверный кэш.

Один суточный цикл загружает все публичные страницы отзывов организации `223039913433` — сейчас это две HTTP-страницы, 50 и 21 отзыв. Дополнительные запросы изображений нужны только для новых вложений. Это разбор JSON внутри публичного HTML Яндекс Карт, не официальный API с договорной гарантией стабильности. При изменении структуры страницы, CAPTCHA, неполном наборе или ошибке сети сохраняется предыдущий полный кэш.

Перед сетевым запросом время попытки записывается на диск. Повторные посещения, ручной запуск и перезапуск процесса не обходят суточный интервал, включая неудачную попытку. Одновременные вызовы внутри процесса объединяются; блокировка файла защищает от параллельного запуска второго процесса. Незавершённый импорт не публикуется.

Фотографии берутся только из вложений конкретного отзыва; проверяются организация и принадлежность автору. Известные локальные файлы переиспользуются, включая подтверждённый вариант `XXXL`. Новые файлы оптимизируются в WebP до 1400 px и сохраняются до публикации обновлённого JSON. Аватарки и общая фотогалерея организации не импортируются.

## Файлы и команды

| Назначение | Путь |
| --- | --- |
| Проверенный резервный снимок | `src/data/yandex-reviews.json` |
| Публичный источник и проверка пагинации | `server/yandex-reviews-source.mjs` |
| Кэш, блокировка, интервал, сохранение фото | `server/reviews.mjs` |
| API и ежедневный таймер | `server/index.mjs` |
| Текущий полный набор | `data/runtime/reviews/snapshot.json` |
| Время попытки, успеха и безопасный код ошибки | `data/runtime/reviews/status.json` |
| Новые фотографии | `data/runtime/reviews/media/<sha256>.webp` |

Каталог `data/runtime/` исключён из Git. `INQUIRY_DATA_DIR` переносит корень runtime; отзывы располагаются в его подпапке `reviews`.

```sh
npm run dev              # API с таймером и локальный Vite
npm run reviews:status   # состояние, без запроса к Яндексу
npm run reviews:sync     # обновить, только если истекли 24 часа
npm test                 # серверные и существующие предметные тесты
npm run qa:hero          # браузерная проверка главной и отзывов
```

API выдаёт новые фото через `GET/HEAD /api/review-media/<sha256>.webp` с неизменяемым годовым кэшем. Другие имена файлов отвергаются. Браузер не загружает новые фотографии напрямую с Яндекса.

## Условия работы после публикации

Ежедневный таймер работает, пока запущен Node-сервер. После остановки компьютера или сервера пропущенное обновление проверяется при следующем старте. Статический хостинг одного `dist/` не запускает синхронизацию.

Для публикации нужны постоянно работающий `node server/index.mjs`, маршрутизация `/api/` к нему, постоянный доступный для записи runtime-каталог, исходный резервный JSON и `public/images/reviews/`. `sharp` включён в production-зависимости. Публикация в этой задаче не выполнялась.

## Проверка

- 35 тестов проходят: существующие заявки и каталог, суточный интервал, перезапуск, блокировки, сохранение последнего полного набора, новые WebP, API без запуска импорта, пагинация и ограничения источника.
- Реальное первое обновление сохранило все 71 отзыв и 79 фото. Повторный `reviews:sync` вернул `fresh`, время попытки не изменилось после перезапуска и трёх чтений API.
- Тесты нового источника используют локальные фикстуры, без повторных сетевых запросов к Яндексу.
