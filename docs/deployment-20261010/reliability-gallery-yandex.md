## Возврат старого сайта через VPN

Пользователь уточнил: в момент сбоя открывается прежний чёрно-золотой сайт, VPN включён.

На 21:54 МСК приложение работало с 15:38 МСК, NRestarts=0, без OOM; свободно около 3,1 ГБ RAM, диск занят на 28%. Это подтверждает состояние в момент проверки, не гарантирует отсутствие любых прошлых сбоев. В журнале nginx есть TLS `bad record mac` от клиентских соединений; это само по себе не свидетельство падения приложения.

Воспроизведение:

В интерфейсе macOS подтверждены активный клиент v2RayTun и выход в Польше (Варшава). В 22:11 МСК повторная парная проверка с одним доменом/IP дала VPN → Tilda 404 за 0,51 с, прямой en0 → VPS health 200 за 0,04 с. Настройки VPN не менялись. Доказательства: `vpn-final-headers.txt`, `direct-final-headers.txt`.

| Проверка | Результат |
| --- | --- |
| HTTPS `/api/content` через обычный маршрут VPN utun6 | 404, `server: ddos-guard`, `x-tilda-server: 30`, HTML старой Tilda |
| HTTPS с явным IP нового VPS через VPN | Также встречался ответ Tilda, поэтому одного `curl --resolve` здесь недостаточно |
| Тот же домен и IP, `curl --interface en0 --resolve vip2d.ru:443:151.248.116.210` | 200, HTTP/2, JSON текущего каталога, время 1,82 с |
| Новый VPS, localhost + правильный Host/SNI | Новый сайт, health 200 |

Авторитетный a.dns.ripn.net публикует ns5/ns6.hosting.reg.ru, TTL делегации 345600 секунд. Cloudflare, Google и Яндекс DNS возвращают 151.248.116.210. Прежние ns1/ns2.tildadns.com продолжают возвращать 176.57.65.40, TTL A=900. Вероятный механизм возврата старого сайта — старые DNS-данные на стороне VPN/его выходного узла; конкретный резолвер VPN пока не установлен. Открытие нового сайта в одном окне браузера не отменяет воспроизведённую разницу маршрутов.

В Tilda системные A @ и CNAME www не имеют редактирования, форма добавления поддерживает только MX/TXT. Это соответствует [документации Tilda](https://help-ru.tilda.cc/domain). Новая корректная DNS-зона уже настроена; повторная смена NS не выполнялась. Настройки VPN не изменялись, старый сайт не удалялся. Очистка DNS-кэша выходного узла, смена узла или истечение старого кэша находятся вне нового веб-сервера. Нельзя считать работу через VPN полностью исправленной.
