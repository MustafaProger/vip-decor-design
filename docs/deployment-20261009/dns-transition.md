# Проверка перехода публичного домена

9 октября 2026, 22:46–22:49 МСК. Статус: публикация нового сайта через домен ещё не завершена.

## Подтверждённая причина

- Кабинет REG.RU показывает ns5.hosting.reg.ru и ns6.hosting.reg.ru.
- WHOIS TCI, полученный непосредственно с VPS через whois.tcinet.ru:43, уже содержит эти же новые NS. Timestamp базы: 2026-10-09T19:48:01Z.
- Каждый из пяти DNS-серверов зоны .ru (a/b/d/e/f.dns.ripn.net), опрошенный непосредственно с VPS без рекурсии, всё ещё публикует ns1.tildadns.com и ns2.tildadns.com. TTL делегации 345600 секунд; это не обещанный срок переключения.
- Оба старых DNS Tilda возвращают A 176.57.65.40 с TTL 900; www является CNAME основного имени.
- Оба новых DNS REG.RU возвращают A 151.248.116.210 для основного имени и www. Лишних AAAA и CAA у основного имени не обнаружено.
- Резолверы Cloudflare 1.1.1.1 и Google 8.8.8.8 пока возвращают старый A.
- В Chrome основное имя открывает старую страницу с заголовком «Красивые шторы на заказ!», /admin — оформленную «ОШИБКА 404». Это старый сайт Tilda, не ответ нового приложения.

Изменение NS зарегистрировано в базе реестра, но ещё не опубликовано в DNS зоны .ru. После публикации дополнительно должны обновиться кеши рекурсивных резолверов. Ускорить этот этап настройкой nginx или перезапуском приложения нельзя.

## Возможность обхода через старую зону

Проверен авторизованный редактор DNS Tilda: основные A/CNAME не имеют кнопки редактирования; форма добавления предлагает только TXT и MX. Перенаправить старый A на VPS через доступный интерфейс нельзя. Новых DNS-записей в ходе этой проверки не создавалось. Документация Tilda также описывает TXT/MX и использование другого NS-хостинга для произвольных записей: https://help-ru.tilda.cc/tilda-dns и https://help-ru.tilda.cc/domain.

- Существующие учётные данные из локального файла доступов: login 200, authenticated=true; проверка сессии 200; logout 200. Cookie Secure. Пароль не менялся, секреты и cookie не записывались в отчёт.

## Условия завершения

1. Серверы зоны .ru публикуют новые NS; рекурсивный DNS VPS разрешает vip2d.ru и www.vip2d.ru только в 151.248.116.210.
2. Существующий таймер выпускает двухдоменный сертификат через HTTP-01, включает HTTPS 301 www → vip2d.ru и отключается. Это ожидаемое поведение проверенного скрипта deploy/finish-tls.py; успешный выпуск ещё не наблюдался.
3. Проверить оба HTTPS-имени, HTTP/HTTPS-редиректы с путями, новый сайт и вход CMS через публичный браузер. Затем certbot renew --dry-run --cert-name vip2d.ru.

Не считать готовность VPS завершением перехода домена. Публичный вход CMS и www HTTPS остаются непроверенными до выполнения условий выше. Изменения проекта не закоммичены и не отправлены в Git.

Это ограничение текущей проверки, не доказательство остановки VPS. Сервер, службы и конфигурация в этой проверке не изменялись.

Это состояние копии на 22:38 МСК, не новый замер серверного журнала.

- По локальным конфигурациям сохранены webroot HTTP-01, проверка обоих DNS имён перед выдачей, ограничение повторных попыток раз в час, nginx -t с восстановлением конфигурации при ошибке, reload и отключение одноразового таймера после успеха. Живое выполнение и продление по-прежнему требуют проверки с доступом к VPS и после смены публичного DNS.

Вывод: задержка публикации делегации всё ещё непосредственно подтверждается. Утверждение «всё настроено правильно и осталось только ожидание» полностью заново не подтверждено: текущая проверка VPS/таймеров/WHOIS ограничена сетевым доступом. После восстановления SSH повторить проверку служб и сертификатов, затем условия завершения выше; не менять делегацию обратно только из-за этой сетевой ошибки.
