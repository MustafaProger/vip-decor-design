# VIP DECOR DESIGN

Сайт компании: React 19, TypeScript, Vite и Node.js. Каталог, блог и заявки управляются через CMS `/admin`.

## Запуск

Нужен Node.js **24.15 или новее**.

```sh
npm ci
npm run dev
```

Сайт и CMS: `http://127.0.0.1:5180`; API: `http://127.0.0.1:3001`. Первый вход: `npm run cms:open`. Настройка администратора и резервных копий описана в [инструкции CMS](docs/CMS.md).

```sh
npm test          # проверки каталога, расчётов, CMS и серверного API
npm run build     # TypeScript, клиентская сборка и серверный рендеринг блога
npm start         # собранный сайт и API на 127.0.0.1:3001
npm run qa:cms    # браузерная проверка CMS на временной базе после сборки
```

`npm run preview` запускает просмотр сборки на порту 4173; для CMS и API отдельно нужен `node server/index.mjs`. Для размещения сайта используйте `npm start`, постоянное хранилище и HTTPS reverse proxy — [подробнее](docs/CMS.md#запуск-собранного-сайта).

## Структура проекта

| Каталог | Назначение |
| --- | --- |
| `src/` | Интерфейс, бизнес-логика и исходные данные первого импорта |
| `server/` | CMS, API заявок, отзывы и серверная выдача сайта |
| `content/blog/` | Статьи и рубрики для первого импорта CMS |
| `public/` | Рабочие изображения, видео, шрифты и их лицензии |
| `scripts/` | Сборка, подготовка данных, проверки и инструменты импорта |
| `tests/` | Проверки каталога и расчётов; серверные тесты также лежат в `server/` |
| `docs/` | Инструкции по эксплуатации и интеграциям |
| `data/runtime/` | Локальная база CMS, заявки и загруженные файлы; исключены из Git |

`src/data/site-content.json` содержит нормализованный снимок 41 страницы, 477 товаров и 28 фотографий работ. Он нужен для первого импорта; это не временный файл. После импорта правки вносятся через `/admin`, а публичный каталог читает `/api/content`. Совместимый адрес `/data/site-content.json` также возвращает данные CMS. Блог отдаёт актуальный HTML с сервера.

## Проверки интерфейса

При запущенном `npm run dev` доступны `npm run qa`, `npm run qa:redesign`, `npm run qa:keyboard`, `npm run qa:media` и остальные команды `qa:*` из `package.json`. Браузерным проверкам нужен установленный Chrome. Проверки блога запускаются против собранного сайта: `QA_BASE_URL=http://127.0.0.1:3001 npm run qa:blog`.

Отдельные сценарии: `node scripts/qa-catalog.mjs` (по умолчанию preview на 4173) и `node scripts/qa-header.mjs` (dev на 5180). Скриншоты и отчёты создаются в `docs/qa/` и `docs/qa-*/`; они исключены из Git. Сохранённые результаты прошлых запусков не нужны для сборки и обычного полного прогона проверок.

## Данные и обслуживание

Рабочую папку `data/runtime/` необходимо сохранять и резервировать отдельно от Git. Она содержит редакторские изменения и персональные данные заявок. Исходные JSON и `dist/` не заменяют её резервную копию. Инструкция: [CMS](docs/CMS.md#где-лежат-данные).

Старые макеты, ZIP-комплекты, исходная выгрузка Tilda и разовые отчёты убраны из рабочей версии. При необходимости исходный снимок доступен в истории Git на коммите `8697791`. Поля `snapshot` и `sourceSnapshot` в исходных данных указывают на файлы той исторической выгрузки; сайт их не читает.

Для отдельного повторного импорта сохранены скрипты, выполняемые по порядку: `python3 scripts/crawl_source.py`, `python3 scripts/crawl_refine.py`, `node scripts/crawl_optimize_media.mjs`, `python3 scripts/crawl_verify.py`. Нужны Python-пакеты `requests` и `beautifulsoup4`. Импорт читает публичный сайт, перезаписывает нормализованные JSON и изображения, создаёт локальные `data/source/` и `docs/CONTENT_INVENTORY.md`. Запускайте его только для осознанного повторного переноса с предварительным сохранением нужных данных; для разработки, сборки и запуска он не требуется.

Временные `dist/`, `*.tsbuildinfo`, кэш Vite в `node_modules/.vite/` и результаты QA можно удалять, когда использующие их процессы остановлены. Зависимости `node_modules/` восстанавливаются через `npm ci`. Рабочие изображения в `public/` и хранилище CMS к временным файлам не относятся.
